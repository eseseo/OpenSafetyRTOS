## 2. 정오표: 선행 검토 기록의 Table 4 계산 오류 (공식 정정)

ISO 26262-3:2018 Table 4 전체 행렬 대조 결과, 선행 검토 기록의 다음 판정은 **수치적으로
오류**였다:

| 위치 | 기재 내용 | Table 4 정답 | 오류 성격 |
|------|----------|-------------|----------|
| OSR-CR-HARA-001 ISSUE-001 / OSR-CR-HARA-002 §2 ("Table 4 기준 정확") | H-05: S2×E4×C2 → ASIL-C | **S2×E4×C2 = ASIL-B** | 1등급 과대 (보수적) |
| OSR-CR-HARA-002 §2 ISSUE-002 확인 ("수치 검증 완료") | H-09: S3×E2×C3 → ASIL-C | **S3×E2×C3 = ASIL-B** | 1등급 과대 (보수적) |
| OSR-CR-HARA-002 §2 ISSUE-002 확인 ("수치 검증 완료") | H-10: S3×E2×C3 → ASIL-C | **S3×E2×C3 = ASIL-B** | 1등급 과대 (보수적) |
| OSR-CR-HARA-001/-002 (무지적 통과 — v1.0부터 잔존) | H-07: S3×E2×C3 → ASIL-C | **S3×E2×C3 = ASIL-B** | 1등급 과대 (보수적) |

참고 대조 (동일 검토에서 올바르게 계산된 항목): H-04 S3×E4×C2 = **ASIL-C** (정확),
S3×E4×C3 = ASIL-D (정확), S3×E3×C3 = ASIL-C (정확).

**평가:** 오류 방향이 모두 보수적(상위 등급)이므로 안전 측면의 즉각적 위험은 없었다.
그러나 "독립 수치 검증"을 선언한 검토 기록이 Table 4를 비일관하게 적용한 것은 검토
프로세스 결함이며, OSR-CR-HARA-002 §2 ISSUE-003 확인란의 자기모순 문장("ASIL-C가 아닌
ASIL-C")과 함께 OSR-ISSUE-002 (Class B)로 등록되었다. 본 정오표가 공식 정정이다.

## 3. D3 확인 — H-05/H-07/H-09/H-10 ASIL 표기 정정 (Table 4 정합 + 문서화된 보수적 상향)

|--------|-------|------------------------|-----------------|----------------|
| H-05 | S2/E4/C2 | **ASIL-B** | ASIL-C (보수적 상향) | ✅ — E 파라미터 불확실성(데드락 노출 시간 논증의 SEooC 한계) 및 H-07 연쇄 시나리오 근거 기재 (HARA-NI-005) |

- 하류 영향 없음: FSC/SSRS는 이미 적용 ASIL(C) 및 개발 수준(D) 기준으로 작성됨. ✅

## 4. D6 확인 — §1.4 분석 범위 정정 (안전 메커니즘을 무력화하는 HW 고장 포함)

**원래 문제:** v1.2까지 §1.4는 하드웨어 레벨 고장을 포괄적으로 분석 범위 외로 두는 취지로
읽힐 수 있었으나, H-09(클럭)/H-10(전원)은 바로 그 하드웨어 고장이 **안전 메커니즘 자체를
무력화**하는 경우로서 이미 위험원으로 채택되어 있어 범위 기술과 위험원 목록이 상충하였다.

**v1.3 반영 내용 확인:**
- §1.4가 "일반 하드웨어 기능 고장은 통합자 시스템 레벨 책임(AoU 위임)이되, **OpenSafetyRTOS의
  안전 메커니즘(MPU 보호, 타이밍 감시, 워치독)을 무력화하는 하드웨어 고장 모드는 본 HARA의
  분석 범위에 포함**"으로 정정됨. ✅
- H-09/H-10 채택과 범위 기술의 상충 해소, 제외 항목에는 AoU 위임 근거 명시. ✅
- OSR-AOU-001 v1.0 정본 레지스트리와의 참조 정합 확인 (AoU ID 충돌 해소 — OSR-ISSUE-003). ✅

## 5. D7 확인 — SG-04 검증 가능 재정식화

**원래 문제:** SG-04 "오탐으로 인한 불필요한 Safe State 전이 최소화"는 "최소화"가 합격
기준을 정의할 수 없는 비검증형 표현 (Part 3 Cl.6의 안전 목표 검증 가능성 요건 미충족).

**v1.3 반영 내용 확인:**
- SG-04가 검증 가능한 형태로 재정식화됨: 실제 위험 조건이 부재할 때 Safe State Level 2
  이상으로의 전이를 유발하지 않아야 하며, 단일 검증 실패 등 일시 이벤트에는 Level 1
  (재시도) 응답을 상한으로 함 — FSR-04-02/FSR-06-04의 N=3 프레임워크와 정합. ✅
- 검증 방법 연결 가능: 오탐 주입 테스트(정상 데이터 + 단일 비트 오류 회복 시나리오)에서
  Level 2+ 전이 부재를 Pass/Fail로 판정 가능. ✅

## 8. 독립성 선언 (Honest Independence Statement)

본 검토자(Agent-QA)는 피검토 문서 작성자(Agent-Safety)와 별개의 에이전트이나, 두 에이전트
모두 단일 유지관리자가 운영하는 AI 인스턴스로서 ISO 26262-2:2018 Table 1의 인적/조직적
독립성 기준으로는 **I2에 미달(sub-I2)** 한다. 본 기록은 ISO 26262 적합 확인 조치가 아닌
검증 지원 조치이며, 외부 ISA 확인 검토의 준비 자료로 사용된다 (docs/TEAM.md v0.5,
OSR-ISSUE-005 참조). 선행 검토 기록들의 "Part 2 독립성 요건 충족" 문구는 본 선언으로
정정된다.
